How speech becomes text, how the answer becomes speech, and why the service never goes silent.

2. IVR Call Flow (Vapi custom-LLM integration)

The server exposes an OpenAI-compatible endpoint that Vapi's assistant calls every turn: POST /webhook/vapi/chat/completions (handleVAPICustomLLM in src/channels/ivr/index.ts).

  1. Vapi transcribes the caller's Hindi speech (talkscriber/Whisper) and sends an OpenAI-format messages array to our endpoint.
  2. Endpoint supports both stream: true (SSE chunks — data: {"choices":[{"delta":…}]} … data: [DONE]) and plain JSON.
  3. The endpoint authenticates the request with VAPI_LLM_SECRET passed as ?key= in the assistant's model.url (401 otherwise).
  4. Call identity: the assistant's system message carries CallRef: {{call.id}}; the server maps the call to a session via sessions.external_ref = 'vapi:<callId>' — so every call is one persistent case record.
  5. Same pipeline as web: language detect → retrieve (top-5, BM25) → generateAnswer with the voice prompt (20b model first, temp 0.7, ≤4 history turns, 250-char passages) → answer returned to Vapi → Naina speaks it.
  6. End of call: /webhook/vapi/call receives the report; if the session somehow has 0 turns, artifact.messages is backfilled (dedupe guard) and the session is marked ended.
// Voice prompt rules (groq.ts) — a LIVE phone call, not a FAQ document
// 1. React to the caller's exact words; never repeat phrasing across turns.
// 2. Greet only on the first turn; never greet again mid-call.
// 3. Everyday spoken Hindi, warm ("जी", "चिंता मत कीजिए"); no jargon, no markdown.
// 4. Ask ONE follow-up question when a detail is missing.
// 5. Empathy in your own words — vary it every time.
// 6. 2–4 short spoken sentences per turn.
// 7. FORBIDDEN on calls: "नीचे देखें", website/app/link mentions, bullets, tables.
// 8. Out-of-domain → exact boundary message (verbatim).

3. Local Vosk STT Worker (kiosk / PWA)

The Node server spawns a long-lived Python worker (scripts/vosk_worker.py) that keeps the Vosk model loaded in memory — no reload per request. Node talks to it over a JSON-lines stdin/stdout protocol:

// Node side — src/modules/stt/vosk.ts
this.process = spawn('python', ['scripts/vosk_worker.py'], {
  env: { ...process.env, VOSK_MODEL_PATH: process.env.VOSK_MODEL_PATH || 'models' }
});
// requests:  {"type":"transcribe","id":"…","path":"…wav","lang":"hi"}
// responses: {"type":"ready"} | {"type":"transcript","id":"…","text":"…","is_final":true} | {"type":"error",…}
  • Model: vosk-small-hi-0.22 stored locally in models/ — no cloud STT dependency on the kiosk.
  • Pre-warm: workers are created at server boot (~5 s model load), so the first user request is fast.
  • Self-healing: isAlive() checks; on worker exit all pending requests reject and the next call respawns the worker.
  • Windows fix: the Python workers reconfigure stdin/stdout to UTF-8 (sys.stdin.reconfigure(encoding='utf-8')) — the cp1252 default silently corrupted Devanagari and blocked buffers (verified: /tts returns 53 KB MP3, /stt transcribes Hindi correctly).
  • Empty transcript guard: if nothing was heard, the API politely re-asks — “Mujhe aapki awaaz sunai nahi di. Kripya dohrayein.”
